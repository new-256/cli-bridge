# 审计：DSH 0.2.1 预设契约漂移修复（2026-10-18）

> 起因：用户使用 **agy 优先模式**时整轮失败 ——
> `unknown prompt variable "{{cwd}}" in section "deployment:persona-suffix"; registered variables: provider, model`
>
> 修复范围：本仓（`@luchenglong/cli-bridge`）+ 姊妹仓 `agy-first-bridge`。
> 本文是**修复方案 + 结果审计**存档（用户规则 #29），并与 `docs/HANDOVER.md` §12 速查表互相索引。

---

## 1. 根因

DSH 的提示词组装器 `interpolate()`（`dsh-system-prompt/lib/index.js:158-182`）对 `{{name}}` 做**严格解析**：

| 判据 | 源码 | 违反后果 |
|---|---|---|
| 完整 `{{…}}` 组 | `GROUP_AT = /^\{\{([^{}]*)\}\}/`（:65） | 有 `}}` 却不成组 → `malformed prompt variable reference` |
| 名字形态 | `VARIABLE_NAME = /^[a-z][a-z0-9_]*$/`（:63） | `{{cwd }}`（含空格）也算 malformed |
| **必须已注册** | `if (!Object.hasOwn(variables, name)) throw`（:172-174） | `unknown prompt variable` |

关键：它在**任何模型请求之前**、组装系统提示词时抛错 ⇒ 整个回合失败，且该预设**完全不可用**（不是降级、不是警告）。

**当前只注册两个变量**（已全量取证）：

- `dsh-agent-loop/lib/index.js:1591-1592` —— `provider` / `model`，全仓无第二个注册点。
- 官方 `dsh-system-prompt/README.zh.md:72` —— 工作目录改由 working-directory 服务以
  **不执行插值的用户上下文**提供；`:78` 明确要求从 preset 的 `suffix` 字段移除该句。
- 实装 `dsh-web-app@0.2.1-alpha.5` 的 `presets/{standard,ptc,cordis,minimal}.patch.yml`
  的 persona **只有 `prefix`**，没有 `suffix`。

**为什么现在才炸（漂移性质）**：上游预设在 `0.1.5-rc.2` ~ `0.1.7-rc.1` 期间**确实带**这句
（`agy-first-bridge/.probe/wa-*` 逐版留证 16 处），到 `0.2.1-alpha.5` 才移除。
本仓预设从**旧版上游模板转录**而来 ⇒ 继承了被上游删除的 suffix。
属"上游改版、下游转录物陈旧"型漂移，**不是**当初写错。

## 2. 第二类缺陷（同一主题，独立成因）

排查"还有没有同类问题"时又查出两类 **dsh-tool-subagent 契约漂移**：

| 字段 | 0.2.1 行为 | 证据 | 影响 |
|---|---|---|---|
| `persona` | **显式 throw** | `dsh-tool-subagent/lib/index.js:355`：`for (const field of ["persona","toolFilter"]) if (Object.hasOwn(config, field)) throw new Error("tool-subagent: … is no longer supported; configure persona and tool plugins in an Agent Preset and select it with agentPreset (spawn only)")` | **mimo 预设整个挂载失败** |
| `toolFilter` | 同上 | 同上 | 同上 |
| `backgroundMode` | **静默忽略（非丢弃）** | 该字段已从 DSH 全部包消失（实测全仓 0 命中）；且实装 schema **会放行**它 —— 见下方更正 | 声明 `continuable`/`one-shot` 却毫无效果，**运行时不报错** |

> **⚠ 机制更正（2026-10-18 独立验证查出）**：初稿写"`Config` 不是 strict ⇒ 被静默丢弃"是**错的**。
> 用实装包双路径实测：`Config({provider, backgroundMode})` 与 cordis 真正走的
> `Config['~standard'].validate(...)`（`cordis/lib/index.js:958`）**都无 issues 且把该键原样保留**；
> `Config.strict` 为 `undefined` —— schemastery **根本没有 strict 开关**。
> 正确表述：未知/已删键**通过校验并被保留**，随后**无人读取** ⇒ 静默**忽略**。
> 这条更正很关键：正因为校验放行，**运行时永远抓不到这类死字段**，静态闸门是唯一防线；
> 而"schema 会丢"的错误表述会让人误以为 schema 层已兜住。
> 附带影响：键被保留 ⇒ 任何对 config 的反射/对比/序列化都可能把它当**幽灵设置**暴露出来。

当前 `Config` 接受：`provider` / `toolName` / `modelSelectionSettings` / `agentOptions` /
`agentPreset` / `allowedAgentPresets` / `maxDepth`。

## 3. 修复方案

### 3.1 变量契约（`{{cwd}}`）

删除所有 preset 的 persona `suffix`，保留 `prefix` 的 `{{model}}`。与官方预设形态一致。

| 文件 | 性质 |
|---|---|
| `preset/standard-base.mjs` | **源头**（共享基座；codebuddy 经它继承） |
| `preset/agy-first/plugin-list.mjs`、`preset/mimo-first/plugin-list.mjs`、`preset/opencode-first/plugin-list.mjs` | **源头**（各自 persona 覆盖） |
| `preset/{agy,codebuddy,mimo,opencode}-first/agent.cordis.yml` | **生成物** —— 由 `node scripts/build.mjs` 从上述源头重新生成 |

> ⚠️ 只改生成物无效：`npm test` 里的 `build --check` 会判漂移失败。

### 3.2 死字段（`backgroundMode`）

从 `preset/standard-base.mjs` 的委派组四行中删除。

### 3.3 mimo 委派人设 → 成员预设（迁移，不删能力）

0.2.1 的契约是"人格与工具面放进独立 Agent Preset，由委派行经 `agentPreset` 选择"。
新增成员预设 + 让 spawn 行引用它，**保留**"子 agent 优先把活派给 mimo_run"这一能力。

| 新增/改动 | 内容 |
|---|---|
| **新增** `preset/mimo-member/plugin-list.mjs` | 成员预设单源：人格（旧委派指令 verbatim）+ mimo 桥接工具面（子 agent 必须能调 `mimo_run`）+ 只读文件面（旧 `toolFilter` 白名单的新表达：`write/edit: false`） |
| `preset/mimo-first/plugin-list.mjs` | 删 `persona`/`toolFilter`；**仅 spawn 行**加 `agentPreset: cordis-mimo-member`（`fork` 与外部后端会 reject 该字段） |
| `home-plugin/…/lib/preset-declarations.mjs` | 新增 `declareMemberPresets()` 并在主预设**之前**注册；导出 `memberPresetIds()` 供测试派生 |

**可行性取证（关键，避免了错误的实现路径）**：

```js
// dsh-agent-preset-registry/lib/index.js
async register(definition) { … this.definitions.set(definition.id, record) }   // :470-479 写
readDocument(agentPreset) { const record = this.definitions.get(agentPreset) … } // :613 读**同一个 Map**
```

而委派行 `validate()` 正是用 `presets.readDocument(id)` 校验引用
（`dsh-tool-subagent/lib/index.js:228-232`，未注册即 `agent-preset/not-found`）。
⇒ **动态 `register()` 与 bundle 行声明互通**，无需改用 bundle 行，
因而不破坏本包"旧 DSH 上不因行 import 失败而整包拒挂"的既有设计（见 `cordis.patch.yml` 头注）。

顺序要求：成员预设**先于**主预设注册（kexi-crypto v1.9.21 同款结论）。

## 4. 防回归闸门

新增 `tests/keystone/persona-prompt-vars.test.mjs`（15 项），三层同时覆盖：

1. **内存单源层** —— 对 5 个 preset 目录（4 provider + 1 成员）的 `buildPlugins()` 输出断言：
   - persona 的 `prefix`/`suffix` 里每个 `{{var}}` ∈ `['provider','model']`；
   - `suffix` 必须缺席；
   - `tool-subagent` 行不含 `persona`/`toolFilter`/`backgroundMode`。
2. **磁盘生成物层** —— 对 4 个 `agent.cordis.yml` 全文同样断言（防只手改生成物）。
   字段用**键正则** `(^|\n)[ \t]*<field>[ \t]*:` 匹配，而非子串 —— 否则
   `name: '@deepseek-ai/dsh-persona'` 与 `- id: persona` 会误报。
3. **跨文件一致性层** —— 委派行引用的 `agentPreset` 必须等于成员预设的 `meta.id`，
   且只允许出现在 `provider: spawn` 行上（fork/外部后端会 reject）。

`tests/keystone/scheduling-gate.test.mjs` 与 `tests/mimo/plugin-list.test.mjs` 同步改造：
注册顺序期望改为 `[...memberPresetIds(ids), ...provider presets]`（从单一源派生，不硬编码）。

## 5. 验证结果（本机实测）

| 命令 | 结果 |
|---|---|
| `node scripts/build.mjs --check` | `[build] up to date`，exit 0 |
| `node --test` | **373 tests / 372 pass / 0 fail / 1 skipped**，exit 0（20.5s） |
| `node scripts/verify.mjs` | `verify: OK`（含导出目标、四 provider 描述符、凭据扫描 201 文件） |
| `node mcp/cli-bridge-mcp.mjs --check` | `"errors": []`，exit 0 |
| 静态复核 | mimo 生成物含 `agentPreset: cordis-mimo-member`、**无** `persona:` 字段、无 `backgroundMode`、4 个 yml 均无 `{{cwd}}` |

**闸门"确实会红"取证**（临时注入缺陷 → 跑闸门 → 还原，三次均按**正确原因**变红）：

| 注入的缺陷 | 闸门报错 |
|---|---|
| 删掉 spawn 行的 `agentPreset` | `本 provider 应至少有一行经 agentPreset 选择成员预设` |
| 把 `persona` 写回 spawn 行 | `tool-subagent 行 'tool-subagent' 仍带已删除字段 persona` |
| 成员预设 `id` 改成 `cordis-mimo-member-TYPO` | `tool-subagent 行 'tool-subagent' 的 agentPreset 与成员预设 id 不一致` |

另：`{{cwd}}` 的闸门在修复过程中亦已实测会红（写回后 `agent.cordis.yml 引用了未注册变量 {{cwd}}`）。
全部场景还原后复跑均恢复绿。
