# 审计：DSH 0.2.2-rc.3 预设契约漂移 ——「opencode-first / codex-first 加载失败」（2026-11-15）

> 起因：用户贴出 DSH「设置 → Agent 预设」截图，`opencode-first` 与 `codex-first`
> 两张自定义预设卡片出现红色 **加载失败** 徽章（自定义分组，卡片描述截断但 id 可辨）。
> 目标：评估并修复 CLI Bridge 插件，而不是绕过或降级。

## 1. 根因（两处，自动化闸门同步变红佐证）

实装 DSH 0.2.2-rc.3（2026-11-14 由 Desktop 插件通道升级）相对本仓 0.2.15 基线
（2026-10-18 修复时对齐的 0.1.7/0.2.1 官方 standard 写法）有两处契约删除：

| # | 行 | 2026-11-14 后状态 | 后果 |
|---|---|---|---|
| 1 | `tool-subagent-list-agents`（`@deepseek-ai/dsh-tool-subagent-control/list-agents`） | 该包 `exports` 只剩 `.`、`./src/*`、`./package.json`、`./locale/*.json`；`./list-agents` 子路径删除（`lib/list-agents.js` 仍在但**导出不可达**） | 预设挂载时该行 **import 失败**（`ERR_PACKAGE_PATH_NOT_EXPORTED`，Node ESM 严格走 exports 表）⇒ `mountPreset` 审计判定 rows failed ⇒ 预设整体拒挂 ⇒ roster `broken` ⇒ 卡片「加载失败」 |
| 2 | `tool-subagent` spawn 行的 `modelSelectionSettings: true` | 字段从 schema 删除；schema 现接受 `modelSelection` / `modelDiscovery` | 未知键被 schemastery 原样保留但无人读取（静默忽略）⇒ 委派永不出现「子 agent 模型可选」能力；且契约测试键集比对变红 |

第 1 处是**挂载级致命缺陷**（整轮预设不可用），第 2 处是**静默失效**（运行不报错，能力缺失）。

证据：
- `node --test tests/keystone/preset-config-contract.test.mjs`（修复前）：7 个用例中 6 个 provider
  预设逐行标 `WARNING 未校验: … tool-subagent-list-agents`，汇总用例硬失败
  （「树在却解析不到 = 真实的契约破裂」设计如此）；修复后 0 未校验 / 0 不符：见 §3。
- `import.meta.resolve('@deepseek-ai/dsh-tool-subagent-control/list-agents')` 以
  `backend\dsh\node_modules\@deepseek-ai\dsh\package.json` 为 base 实测抛
  `ERR_PACKAGE_PATH_NOT_EXPORTED`（2026-11-15 实测）。
- 当前 0.2.2-rc.3 的官方 `standard.patch.yml`（`dsh-web-app/presets/`）无 list-agents 行、
  spawn 行为 `modelSelection: true / modelDiscovery: true`、`tool-subagent-control` 带
  `config: { interrupt: false }`（实装包 schema `dict=[interrupt]`，缺省 true，上游显式关掉
  `interrupt_agent` 工具）。

为什么表现为「所有新增 provider 预设都坏、旧包时代预设之一（mimo）只挂成员预设」：
六个预设共用同一单源基线（`preset/standard-base.mjs`），list-agents 行是**每个预设都有的
共享行**——一个致命行抹掉全部六家。用户截图里可见的两张卡（opencode-first / codex-first）
是启用列表（agy/opencode/claude/codex）里恰好被截取/浏览到的两张，**其余三个 provider
预设及 agy/claude 同样挂载失败**（同一根因）。成员预设 `mimo-member` 无该行，保持完好。

## 2. 修复范围（能改的最小面）

`preset/standard-base.mjs`（单源，影响六个 provider 预设 + 与 mimo 成员预设无交集）：

- **删** `tool-subagent-list-agents` 行（上游已将 list_agents 能力并入 `dsh-tool-subagent-control` 主模块）；
- **改** spawn 行：`modelSelectionSettings: true` → `modelSelection: true, modelDiscovery: true`；
- **改** `tool-subagent-control` 行：补 `config: { interrupt: false }`（对齐上游 schema `interrupt`）；
- **删** `tool-ralph` 行（与上游对齐；ralph 能力由 `@deepseek-ai/dsh-experimental-ralph-bundle` 以 bundle 注入，本 profile 已装该 bundle）；
- **增** `time-context`（`@deepseek-ai/dsh-time-context`）、`tool-schedule`（`@deepseek-ai/dsh-tool-schedule`）、`tool-office`（`@deepseek-ai/dsh-tool-office`）、`tool-plugin-market`（`@deepseek-ai/dsh-plugin-market/tools`，disabled）行；
- **改** `tool-fs` 行：`config: { applyPatch: false }`（对齐上游；dict 含 `applyPatch`）；
- **改** plan-mode 段落首句：跟随上游 0.2.2-rc.3 逐字（「until the user approves your plan through exit_plan_mode …」）；
- **保留** `tool-plugin-manager` 恒 `disabled: true`（上游为 `!!js "!ctx.get('profileContext')"`；web profile 行为等效，且桥接代理不该自改组合，属有意差异）；
- **未引入** `skill-filesystem` 的 `customSkillDirs`（上游用 `createRequire(baseUrl)` 解析 dsh 安装树内
  `@deepseek-ai/dsh-agent-preset/skills`；本包声明制预设的 baseUrl 继承自 profile
  （`profiles/web/` 下 `createRequire` 无法解析该包，实测 MODULE_NOT_FOUND），该表达式会在
  预设挂载时再次抛错。属 0.2.1 时代同类事故，禁止照抄）。

消费方同步：
- `tests/keystone/persona-prompt-vars.test.mjs`：`REMOVED_TOOL_SUBAGENT_FIELDS` 增加 `modelSelectionSettings`；注释更新至 0.2.2-rc.3。
- `tests/keystone/preset-config-contract.test.mjs`：注释更新（list-agents 子路径已下线并从单源删除）。
- `tests/mimo/plugin-list.test.mjs`：基线行数 19 → 23（23+1 = 24）。
- `agent.cordis.yml` 全部六份生成物：`node scripts/build.mjs` 重新生成并入库（`build --check` 防漂移）。
